# Pièges vérifiés — serveur « FoodEatUp tutoriel » (session live du 2026-10-25)

Comportements constatés en appelant réellement le serveur (v0.7.0). À relire
avant d'écrire un workflow qui dépend d'un de ces outils.

| Outil | Piège constaté | Parade |
|---|---|---|
| `rechercher_tutoriels` | Le paramètre s'appelle `question` — `q` renvoie une erreur -32602. | Toujours `question`. |
| `parcours_apprentissage`, `lecon_suivante` | `niveau` est OBLIGATOIRE (debutant = compte non configuré, intermediaire = bases acquises, avance = automatisation/prompts). | Demander ou déduire le niveau avant l'appel. |
| `quiz_tutoriel` | Pas toujours de QCM : questions `ouverte` et `ordre` quand le catalogue ne permet pas un QCM honnête (le champ `pourquoi` l'explique). La `consigne` du serveur impose : une question à la fois, réponse cachée, renvoi vers le champ `revoir` en cas d'erreur. | Suivre la consigne renvoyée, pas un format supposé. `graine` (date, prénom…) change l'ordre des propositions entre deux passages. |
| `lecteur_video_tutoriel` | Pas de champ chapitres sur les vidéos courtes : la réponse porte `etapes` (à suivre pendant la vidéo) + `lecteurHtml`/`markdown` prêts à l'emploi. | Le widget lecteur-chapitres retombe sur `etapes` quand il n'y a pas de chapitres. |
| `lister_modules` | `videosEnLigne` ≠ `videosPrevues` sur plusieurs modules (relevé du 2026-10-25 : caisse-pos 7/34, api-developpeurs 0/4, reseau-partenaires 0/8, client-restaurant 0/10 — à relire, ça bouge). | Ne JAMAIS promettre une vidéo d'un module à 0 en ligne ; `audit_formation` fait foi sur les manques. |
| `tarifs_et_essai` | La réponse porte `verifieLe` et un champ `prudence` : options, crédits et prestations n'y figurent pas. | Citer la date ; pour tout montant hors réponse, renvoyer vers la page tarifs (`pageTarifs`) au lieu d'improviser. |
| `capacites_foodeatup` | Décrit les domaines du PRODUIT FoodEatUp (`totalOutils` côté produit), pas les 36 outils de ce serveur. La doc API (`documentation_api_foodeatup`) peut annoncer un autre total (193 au 2026-10-25 contre 187 côté capacités) : deux sources, deux dates. | Ne pas harmoniser soi-même : citer l'outil appelé et sa date. Les 36 outils d'ICI se comptent dans la liste versionnée, pas via `capacites_foodeatup`. |
| `parcours_client_restaurant`, `brief_video_client` | Les vidéos du parcours convive ne sont pas tournées (`videosEnLigne: 0` sur client-restaurant). | Jamais de lien vidéo annoncé côté convive ; les briefs décrivent ce qui reste à produire. |
| `brief_video_partenaire` | Ton imposé par le serveur : aucun concurrent nommé, aucune promesse chiffrée. | Relayer tel quel dans tout script écrit à partir du brief. |
| `carnet_de_formation` | `mode` obligatoire (`encoder` en fin de séance, `decoder` au début). Le code ne vaut que ce que `slugsVus` contenait. | Encoder AVANT de clore ; au décodage, confirmer secteur/métier relus. |
| `carte_tutoriel` | Les vignettes sont des URLs distantes ; certains clients ne les affichent pas. | `vignetteIntegree: true` dans ce cas. |
| `tutoriels_du_module` | Le couple `module` + `ecran` vient du hub FoodEatUp (vocabulaire partagé des cinq projets) — un slug de module du CATALOGUE (`lister_modules`) n'est pas toujours un module du HUB. | Partir des `ecrans_logiciel` portés par les fiches, pas d'un slug deviné. |
| `diagnostic_demarrage` | « serveur » n'est PAS un slug de métier : les slugs valides sont ceux que le diagnostic propose (recette du 2026-10-25 : chef-de-cuisine, second, commis, plongeur, responsable-de-salle, chef-de-rang, barman, directeur, chef-de-restaurant). Un slug inconnu laisse `metier` à null et la question reposée. | Faire choisir dans les `options` renvoyées ; ne jamais traduire un intitulé en slug soi-même. |
| `parcours_apprentissage` | Un `metierSlug` inconnu échoue avec « Aucune leçon trouvée… » (message qui renvoie vers `onboarding_foodeatup`/`lister_modules`). La réponse valide imbrique les leçons dans `seances[].lecons[]` (pas de liste plate) et porte `methode` + `exportJson`. | Slug depuis le diagnostic ; les widgets lisent `seances[].lecons[]`. |
| `former_son_equipe` | `metier` est un objet `{slug,label,url}` ; les leçons de démarrage sont dans `premiereSeance[]` (sans durée) avec une check-list `validation` à cocher EN OBSERVANT ; `messageAEnvoyer` est un TEXTE à remettre — le plugin n'a aucun outil d'envoi. | Restituer la validation par observation ; remettre le message, ne jamais dire « envoyé ». |
| `carnet_de_formation` (decoder) | Le décodage renvoie bien plus que l'état : la `leconSuivante` complète (étapes, astuce, question de contrôle) et un `messagePourLUtilisateur`. Le serveur ne garde RIEN : le code est la seule mémoire (champ `note` à l'encodage). | Reprendre directement sur `leconSuivante` ; redire à l'utilisateur que perdre le code = perdre la progression. |
